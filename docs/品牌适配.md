# 品牌适配

桌面接管 Home 键的地方都读 `DeviceProfile`（`launcher/app/src/main/java/com/gathin/tvhome/DeviceProfile.java`）。一台电视需要知道四件事：

| 字段 | 用途 | 来源 |
|---|---|---|
| `stockHomes` | 原厂桌面包名，切到前台就把桌面盖上去 | 品牌表 + 探测（所有声明 `CATEGORY_HOME` 的包） |
| `homeClassSuffixes` | 原厂桌面里哪个页面算「首页」 | 品牌表；空 = 整个包的任何页面都算 |
| `screenSavers` | 原厂待机轮播包名 | 品牌表 + 类名以 `ScreenSaverActivity` 结尾的兜底 |
| `settingsPackages` | 厂商设置 App，系统设置入口打不开时用它 | 品牌表，按安装情况过滤 |
| `allAppsIsHome` | 遥控器的 Home 是否发 `KEYCODE_ALL_APPS` | 品牌表 |
| `accessibilitySettings` | 系统「无障碍」页是否真的打得开；打不开就改弹 ADB 开启指引 | 探测：`ACCESSIBILITY_SETTINGS` 解析到 `com.android.tv.frameworkpackagestubs`（AOSP 死桩）或无解析即为假 |

## 新品牌怎么办

1. 先不动代码，直接装一版。未知品牌走 `generic` 档案，原厂桌面由探测得到，Home 接管应该已经能用（品牌设的 `homeClassSuffixes` 为空，原厂桌面任何页面都会触发覆盖）。
2. 装完打开一次桌面，反馈后台「错误」里会出现一条 `caps`：
   `profile=generic stockHome=[...] screensaver=[...] settings=[...] allAppsHome=false a11ySettings=true sdk=... device=厂商 型号`
   这一行就是这台电视的自述，多数情况照着它补品牌表就行。
3. 需要改行为时，在 `DeviceProfile.BRANDS` 里加一条，关键字匹配 `MANUFACTURER`/`BRAND`/`MODEL`/`DEVICE` 的小写串。只写探测拿不到的东西——能探测到的一律留空。
4. 注意：
   - `homeClassSuffixes` 收窄的是「原厂桌面的哪个页面算首页」。小米就靠 `MainActivityUserMode` 区分首页和信号源/电视页，不收窄会和原厂桌面来回抢焦点。
   - 品牌表里的设置包要真实安装才进 `settingsPackages`（用 `getPackageInfo` 判断，不用 `resolveActivity`，后者会对着没装的包返回能解析）。
   - 新品牌只加档案，不改 `HomeKeyService`/`MainActivity` 里的判断。

## 已知品牌

| 品牌 | 关键字 | 桌面 | 待机轮播 | 设置 | Home=ALL_APPS |
|---|---|---|---|---|---|
| xiaomi | xiaomi / redmi / mitv | `com.mitv.tvhome` + `MainActivityUserMode` | `com.mitv.screensaver`、`com.xiaomi.tv.gallery` | `com.xiaomi.mitv.settings` 等三个 | 是 |
| skyworth | skyworth / coocaa / tianci / 创维 / 酷开 | `com.tianci.movieplatform` + `rootpage.HomeActivity` / `movieplatform.MainActivity` | `com.coocaa.screensaver` | `com.skyworth.setting` | 否 |
| sony | sony / bravia | 探测 | 探测 | 系统设置 | 否 |

创维实测于 8R720_A5FP / 安卓 13（2026-10-23）：整机没有任何 `CATEGORY_HOME` 活动，Home 键由固件直接送到 `com.tianci.movieplatform/…rootpage.HomeActivity`，所以探测拿不到，只能写进档案。它的待机轮播类名是 `com.skyworth.screensaver.ui.MainActivity`，不带 `ScreenSaverActivity` 字样，因此判断规则看类名里有没有 `screensaver`，而不是固定后缀。

创维 85A6E（平台 8R710，`ro.product.model=8R710_A6E`，安卓 13 / SDK 33）实测于 2026-10-24，和 8R720 同包但页面不同：
- Home 键落到的页面，窗口标题是 `com.coocaa.homepage.vast.HomePageActivity`，但它跑在宿主里，无障碍事件上报的类名是宿主 `com.ccos.cooui.movieplatform.MainActivity`。按窗口标题加后缀永远不触发；必须用宿主类名。搜索页（`…search.SearchActivity`）和 `rootpage.HomeActivity` 都上报自己的类名，所以这个后缀不会误伤。
- 整机没有无障碍设置页：`android.settings.ACCESSIBILITY_SETTINGS` 只解析到 `com.android.tv.frameworkpackagestubs/.Stubs$SettingsStub`（AOSP 死桩），`USAGE_ACCESS_SETTINGS` 无解析；`com.skyworth.setting` 里虽然有 `AccessibilitySettingActivity` 类，但 Manifest 没声明，是死代码；设置界面（通用/图像/声音/网络/蓝牙/应用）和工厂菜单（通用设置/高级设置）里都没有。所以 `accessibilitySettings=false` 时桌面不再跳系统页，改弹 ADB 指引（`MainActivity.showAccessibilityGuide`），命令直接写在弹窗里。
- 开 ADB 的唯一入口：设置 → 通用 → 关于本机 → 本机信息 → 更多信息，停在该页按 上上下下左右左右 进酷开工厂菜单（命令行入口 `com.coocaa.factory/.SkyFactory`）→ 通用设置 → ADB开关 → 打开后重启电视。开好后电脑执行 `adb connect 电视IP:5555`，再跑弹窗里的三条 `settings`/`appops` 命令。升级桌面会关掉服务，要重跑。
- 设置入口 `com.skyworth.setting/.Main` 正常；屏保 `com.coocaa.screensaver/com.skyworth.screensaver.ui.MainActivity`。机器上另装了当贝桌面和 `app.orchard.tv`，它们也声明了无障碍服务，和接管不冲突。

小米 HyperOS 3（MiTV-MFFU0 / finch，安卓 14 / SDK 34，固件 OS4.0.11.0.UFFMATV，实测 2026-10-25）：原厂 `com.mitv.tvhome` 已被停用（`DISABLED_USER`），HOME 角色在我们桌面手里。这台机器的坑是包名，不是代码：
- 固件只让 `com.thunderstone.idun.dev` 这个身份当桌面。实测把标准包 `com.gathin.tvhome` 装上、`cmd package set-home-activity` 和 `cmd role add-role-holder android.app.role.HOME` 都返回 Success、`cmd role get-role-holders` 也显示它，但 Home 键和 `ACTION_MAIN + CATEGORY_HOME` 仍然落到 `com.xiaomi.mitv.settings/.entry.FallbackHome`；禁掉 idun 后更是直接没有桌面可用。所以这台机器必须装 idun 渠道，不能装标准包。
- 构建：`:app:assembleIdunRelease`（flavor `idun`，applicationId `com.thunderstone.idun.dev`，Java 包名仍是 `com.gathin.tvhome.*`，代码零改动）。更新清单 `/update-idun.json`，APK 在 `/apk/idun-<code>.apk`；沿用 `update.json` 会下载标准包，安装时报 `INSTALL_FAILED_INVALID_APK ... inconsistent with com.thunderstone.idun.dev`。
- 签名：2026-10-25 之前装在这类机器上的 2.0.9 是别的电脑 debug 签的（证书 SHA-256 `20882a54…`），和我们的 release key（`49b42386…`）不同，覆盖安装必失败，只能卸载重装；卸载前 `adb pull` 旧 APK 留作回滚。卸载后到装好之前 Home 会暂时落到 FallbackHome（设置里的黑页）。
- 无障碍页存在（`com.android.tv.settings/.oemlink.AccessibilitySettingsActivity`），`a11ySettings=true`，不需要 ADB 指引。但 HomeKeyService 默认关着；要在「设置 → 无障碍 → Home 键回顶」打开并允许使用情况访问，否则 Home 键在别的应用里回不到桌面、桌面里按 Home 也不会回顶。
- Home 实测走 `KEYCODE_HOME`（`input keyevent 3` 能回桌面，`285` 无反应）；`allAppsIsHome=true` 保留无害。待机轮播默认关闭（`screensaver_enabled=0`），已装的 `com.xiaomi.mitv.aod.screensaver` / `com.xiaomi.mitv.hyper.screensaver` 类名都带 `screensaver`，现有判断能覆盖。
- 应用内更新在这台机器上装不了，原因全在系统安装器（`MiTVPackageInstallerP_10.5.7`，targetSdk 28）：它没声明 Android 10+ 的 `android.content.pm.action.CONFIRM_INSTALL`，`PackageInstaller` 会话提交后系统拉起确认页直接失败（`result code=-91`），会话永远停在待确认；走 `VIEW` 直接拉安装器界面则一打开就崩 `NoClassDefFoundError: android.content.pm.PackageUserState`（安卓 14 删了这个隐藏类）。另外固件把 `REQUEST_INSTALL_PACKAGES` 改成了 `signature|appop`，第三方应用 `granted=false`（appops 放行能过安装器的第一道检查，但仍会撞上面的崩溃），只有 system uid 的小米应用能装。所以 `Remote.canSelfInstall()` 在「没有 CONFIRM_INSTALL 且安装器 targetSdk < 29」时返回 false，更新只把 APK 用 MediaStore 存到公共「下载」目录，弹窗写清楚手动安装的路子。
- 手动安装只有两条路，实测都通：把 APK 拷到 U 盘插电视，用「电视管家 → U盘安装包」；或者在电脑上 `adb install -r`。媒体中心里点 APK 装不上（还是落到上面那个崩溃的安装器），弹窗不要让人去媒体中心。
- 这台测试机自己更新用 `tools/update-idun.sh [电视IP]`：查 `/update-idun.json`、比版本、下载、`adb install -r`，复用 `install-tvhome.sh` 的连接和报错处理。实测 2.0.14 时电视 55 / 服务器 55 能正确判定「已是最新」。
- 显示与画面：`Settings.ACTION_DISPLAY_SETTINGS` 在这台机器上解析到小米自己的 `DisplaySoundActivity`，类却不在 APK 里，点开崩 `ClassNotFoundException`。回退到 AOSP 的 `com.android.tv.settings/.device.displaysound.DisplaySoundActivity`（「显示和声音」）正常。判断用 `installed()` + 类名，不能只看 `resolveActivity`（声明了不等于有类）。
- 从电视选图片：`ACTION_OPEN_DOCUMENT` 落到 `frameworkpackagestubs` 死桩；`ACTION_GET_CONTENT` 是安卓 14 系统照片选择器，只有触摸能用，遥控器按 OK 没反应、方向键也没有焦点。所以自建图片网格（`popup_photos` + MediaStore 查最近 9 张，`loadThumbnail` 取缩略图）。读图要 `READ_EXTERNAL_STORAGE`（targetSdk 29 仍是运行时权限），权限弹窗遥控器能操作；拒绝授权就退回系统选择器，至少触摸能用。
- 直播电视：`com.xiaomi.mitv.tvplayer` 没声明 launcher category，`Televisions` 里也找不到它，但机器有 tuner（HW0/HW1）。输入源弹窗里直接用 `com.xiaomi.mitv.tvplayer.DTMB_PLAY` 拉 `…dtmb.DTMBActivity` 作「直播电视」，首次进入会提示搜台。输入源实测列出 HDMI 1-4 + Composite（`com.mediatek.tvinput` 的 HW5-HW8/HW2），控件本身没问题。
- 卸载：`ACTION_DELETE -d package:<pkg>` 能拉起 `com.android.packageinstaller/.UninstallerActivity`，遥控器可操作；应用信息入口也正常。

索尼实测于 2026-10-22：标准安卓 TV，桌面和设置都能探测到，不需要品牌字段。当天踩的坑有两个：判断小米设置包时用 `resolveActivity` 返回「已安装」，其实没装（现在统一用 `getPackageInfo`，见 `installed()`）；输入源里每个 HDMI 都被报成已连接，`TvInputs` 里按状态过滤。档案里登记 sony 只是为了反馈里能认出来。
